# M1 通用单图调用接入

业务文件由 F 通过资源包提供，平台只解释受限连接器和已授权 Unit 配置。完整 F 接口约定与 UI 示例在 [ForestHanressEngineeringAPIRef.md](../../forest/ForestHanressEngineeringAPIRef.md)。

## 安装与启用

使用 JDK 8 构建 common、service、dispatcher、service-harness、service-harness-skill。通用工具包的作者文件在 `service-harness-skill/harness-tools/{data,capability}`，构建 `packages` 后得到两个真实 ZIP。工具由薄 Runner 通过 Broker 调用 Java Provider；原有普通文本任务和 final 协议保持原用法。

BZ 运维首次安装通用扩展 JAR、发布并授权 `common/data`、`common/capability` 和需要的 `common/time` 工具包。上传业务包不会安装 Java 类。新增的私有配置示例：

```properties
# Append to the existing provider list, keeping other providers.
broker.providers=data,capability
broker.provider.data.class=cube.service.harness.skill.DataQueryProvider
broker.provider.data.config=C:/private/harness/data.properties
broker.provider.capability.class=cube.service.harness.skill.CapabilityInvokeProvider
broker.provider.capability.config=C:/private/harness/capability.properties
# Append permissions to the existing deployment ceiling.
execution.permissions=skill.list,skill.activate,resource.list,resource.read,resource.search,data.query,capability.invoke,time.read,artifact.write_text

# Independent authenticated domain/contact allowlists; none enabled by default.
admin.release.subjects=forest-domain/10010
admin.policy.subjects=forest-domain/10010
admin.source.subjects=forest-domain/10011
admin.source-grant.subjects=forest-domain/10011
admin.tenant.forest-domain.signers=f-author
runtime.signer.f-author=<Base64 X.509 DER RSA public key>
admin.sources.allowedOrigins=https://forest.example.internal
admin.sources.allowedPaths=/api/patrol/records,/api/media/content
admin.sources.secretRefs=forest-source
```

Provider 的 `data.properties`、`capability.properties` 配置同一 `secret.forest-source`；该密钥与 F 签名验证器共享，不能发布在业务包中。管理源码复用原 PackageRepository、ProfileRegistry、CatalogStore；不运行 RuntimeAdmin shell。远程包必须签名，且不允许包含 executable 工具；资源可变更，平台权限和执行器仍由 BZ 运维控制。

M1 视觉桥接要求 AIGC、Harness 与 Auth 同 Kernel/JVM，FileStorage 可用。AIGC 私有 `aigc.properties` 在真实预热验收后配置：

```properties
harness.media.dedicated=true
harness.media.units=OmniMultimodal,OmniPerception,SpecializedDetection
```

该开关表示部署方已为这些节点隔离物理算力；M1 不证明旧视觉接口或主模型共享同一 GPU 时的统一容量安全。默认不开通任何路由，不能把 dummy 或仅有源码的能力启用。多个同能力 Unit 可以接入；同一个 Unit 联系人节点的不同能力共享一个持久物理槽位。分 JVM 部署不能直接取得 AIGC 对象，当前未装配桥接时明确拒绝；跨 JVM 受控转发尚未实现，共享 GPU 完整验证尚未完成。

F 业务包只保留实际启用的分析 profiles；仅主动上传时只保留 snapshot 连接器。创建任务会预检包中全部已声明连接器与分析配置，尚未配置的数据源或离线的分析能力会阻止准入。就绪检查是准入时观察，实际调用仍重新检查授权和容量。

### 专项检测能力

Python `SpecializedDetection` 通过现有 `subtasks` 注册服务，第一项固定 `ObjectDetection`，
后续为实际启用的 `uav-fire-smoke`、`fire-smoke`、`thing`；不修改 `description`。
运行就绪、切片能力及会话上限由独立 `specializedDetectionStatus` 报告提供，30 秒无有效报告即未就绪。
详见 [注册与调度协议](../docs/specialized-detection.md)。媒体发现、任务预检、持久预留和实际发送都检查
profile、切片能力、有效就绪租约与图像余量。同一联系人仍只有一个持久物理槽位，启用三个 profile 不增加槽位。

`analysis-profiles.json` 可以声明通用物体类别过滤：

```json
{"version":"1","profiles":[{"id":"people-vehicles","adapter":"specialized-detection","unit":"SpecializedDetection","mediaTypes":["image/jpeg","image/png"],"optionsJson":"{\"operation\":\"detect\",\"profile\":\"thing\",\"classes\":[\"person\",\"car\"]}"}]}
```

profile 名称为字符串，能力可用性由在线节点确认。`classes` 为非空字符串数组，Harness schema 限制
最多 256 项、单项最多 128 字符；规范类别名称由 Python 校验。未知 options 字段继续拒绝。
工具仍通过绑定的 `inputId`/`mediaRef` 读取图片，由桥接保存到 FileStorage；检测输入只包含 unit、files、option，
不携带文本 `content`。结果完整保留类别契约、模型、工件摘要与检测元信息，沿用原产物封装。

## 存储和恢复

在既有 Harness 专库中增加四个通用元数据表：数据源版本、数据源授权、Provider 事实及管理幂等记录。由现有 `StoreBootstrap` 启动建表、严格结构校验和已知旧版本升级机制管理，不修改旧表字段，不保存图片字节。SQLite/MySQL 使用现有事务、身份和锁机制。Provider 事实绑定 run/job；只有已确认成功调用生成的媒体引用/页游标才能被后续工具读取。

先持久化 job、实例选择及 serviceSn，再发送视觉请求。媒体字节经现有 FileStorage 登记给 Unit，实际响应通过现有 Cell 协议回传；thought 不交付。未知执行不重跑；单图等待最多 20 秒，普通工具上限仍为 30 秒。超时和取消不代表远端结束，无物理回执不释放持久槽位。活进程中的迟到响应只回写回执、用量及清理；收到回执后即使结果落库暂时失败，也只重试写回执，不重新推理。

如果整个 service/JVM 丢失且没有持久物理终止证据，保留 unknown/预留；本版没有自动猜测终止的管理按钮。未知调用的 FileStorage 暂存图在无法确认物理结束时保留，需按部署方已有文件保留策略处理；不能提前删掉仍可能被 Unit 消费的文件。完整故障矩阵与跨进程完成证据仍需真实部署验证。

来源采用现有 UTF-8 文本产物 `media-source.json`。`origin` 由文件账本关联实际 Provider job 推导，包含 operation/jobId/confirmed。F 只接受已确认 `common.capability.invoke.v1` 生成的来源元数据，不接受模型写的同名文件。回放同一调用复用原产物，迟到结果不新增来源或重写历史回答。

## 验证

```powershell
# In service-harness-skill, using actual JDK 8 and Ant:
ant test-media
ant test
# In service-harness, after rebuilding dispatcher:
ant test-transport
ant test-execution test-tools test-control-files
```

`MediaToolsTest` 使用真实签名 ZIP、SQLite、Broker、授权 Input 和本地签名 HTTP F 夹具；视觉桥接是明确标记的替身。这不代替真实三人照片、真实 UNIT、耗时、质量、多 JVM/多节点部署验收。不存在可连接的真实 F 接口或现场模型时，不记录现场通过。
