# M2 数据加工与首次人工部署

本阶段实现配置驱动的过滤、分组聚合、精确去重、查询页覆盖检查和来源保留。代码位于 `service-harness-skill`；沿用已有任务、Broker、普通 Python tool Runner 和 ProviderStore 事实表，不增加 REST 路径、数据库表或 Python 协议。

2026-11-10 状态：M2 实现、实际 Temurin JDK 1.8.0_504 构建与 `ant test` 已通过，包含 29 项加工断言、九套工具包校验及 SQLite/Broker 集成。已检查跨 run 引用拒绝、结果分页、重启读取、授权撤销、跨页来源保留。视觉部分仍为夹具。当前进入“用户人工部署跑通”步骤，再根据实际运行讨论后续验证与 M3。

本机已生成技能扩展 staging：`cube-server/service-harness-skill/build/stage-m2/`，其中 libs 放新 JAR，harness-skill/packages 放九个工具 ZIP。F 示例包为 `forest/build/fhe-patrol-v2.zip`；它锁定本机生成的四个真实工具摘要，部署时须先在 BZ 发布并授权对应 release，或用部署方实际获准的摘要重构 F 包。本地构包不会自动发布或安装。

**可先行部署的节点是 M2。** 配齐下面的 JAR、工具 release、业务包和权限，即可人工跑“取数 → 加工 → 按需单图分析 → 回答和原图展示”。M3 必需步骤门禁、M4 报告结构强校验留待后续；流程目前由 SKILL 指导，加工工具明确返回数据与覆盖情况。先人工部署跑通，部署后的质量、性能和故障验证再另行讨论。

F 的后端接口仍按 [F 接口说明](../../forest/ForestHanressEngineeringAPIRef.md)实现分页查询和按 ID/版本获取原图；主动上传快照继续支持。新增业务配置在 [data-processing.json](../../forest/packages/fhe-patrol/data-processing.json)，必须列入业务包 manifest，由 Provider 显式读取。

## 数据和配置

`common.data.query` 每页新增 `pageRef`，代表当前 run 内已确认成功的查询页。按 nextCursor 取后续页，再按遍历顺序把 pageRefs 交给 `common.processing.process`。模型不能直接提交记录、来源身份、URL 或加工代码。

加工返回不可变 datasetRef、stats、coverage 和首批 itemsJson。action=read 按 offset 续读；view 可选 records 或 groups，nextOffset=-1 表示该视图结束。records 每项含 record 和 sources，后者保留所有 pageRef、mediaRef、媒体 ID/版本、原页行号和时间信任级别。groups 含分组键、聚合值、缺失值计数和指向整个 records 视图的零基 recordIndexes。实际图片分析继续用 sources 中的 mediaRef 调 common.capability.invoke。

页须来自同一 run、业务 skill、connector、查询和 snapshot。缺起始页、缺末页、跳页或顺序错误，coverage.queryComplete=false，并返回 QUERY_PAGES_INCOMPLETE；混合查询或快照直接拒绝。queryComplete 仅表示交给加工工具的查询页链完整，不表示每张图片已分析，也不表示整个林区没有异常。HTTP 来源授权在加工和结果读取时均重查。

精确去重身份为 recordId + recordVersion + mediaId + mediaVersion，内容还须一致；同身份异内容报 DATA_PROCESS_RECORD_CONFLICT。缺记录版本时不合并并返回 warning。不同版本、媒体和连续帧独立保留，不推断跨帧身份或唯一人数。count 统计过滤与去重后的记录行数。

业务文件格式为 `{version:"1",profiles:[...]}`，每个 profile 声明 id、connectorId、inputSchema、filters、deduplicate、groupBy、aggregates。字段名指连接器已经投影的字段，M1 连接器继续负责字段映射。例如：

```json
{
  "version": "1",
  "profiles": [{
    "id": "region-summary", "connectorId": "patrol-records",
    "inputSchema": {
      "type": "object",
      "properties": {"locationId": {"type": "string", "minLength": 1, "maxLength": 128}},
      "required": ["locationId"], "additionalProperties": false
    },
    "filters": [{"field": "locationId", "operator": "eq", "parameter": "locationId"}],
    "deduplicate": true, "groupBy": ["locationId", "locationName"],
    "aggregates": [{"name": "recordCount", "operation": "count"}]
  }]
}
```

filters 按 AND 执行，每项在 value 固定值和 parameter 参数名中二选一。参数须在 inputSchema 声明，调用的 argumentsJson 也须通过它。支持 eq/ne/in/exists、数值 gt/gte/lt/lte，以及带偏移 ISO 8601 时间的 before/after/atOrBefore/atOrAfter。时间按实际 instant 比较。缺失或 null 的比较字段排除并披露；exists 判断是否存在非 null 值。

groupBy 最多四个字段。聚合 count、sum、min、max，后三者须声明 field，使用精确 BigDecimal 并返回十进制字符串。缺失值不当 0；无有效值返回 null，并记录 missingValues；非法数值失败。空数据且无 groupBy 时仍有一条 count=0 的全局汇总。

每次最多 64 页/1024 行、128 组，持久结果最多 1 MiB。返回延续 12 KiB 与 Runner 包装预算；默认每页最多 8 项，limit=1～16，工具按字节预算缩小返回页。必须跟随 nextOffset；单个条目超预算明确失败，不截断来源。整个任务仍受 runtime 的轮次、工具数与时间预算约束，初次人工运行建议 1～2 页。

## BZ 安装和发布

1. 使用实际 JDK 8 与相互匹配的 common、service、dispatcher、service-harness 基线。M1 同 JVM Auth/AIGC/FileStorage、隔离视觉 UNIT 的前提继续适用。多个 model/Runner 仍各自使用独立 workerId、实例身份、runtimeDir、journal 和租约。
2. 在 `cube-server/service-harness-skill/` 执行 `ant build packages`，再执行 `ant stage -Dstage.dir=C:/releases/harness-m2`，Linux 使用对应绝对 staging 路径。该 stage 仅是技能扩展，须合入完整 Harness 部署，不会启动服务。
3. 关闭新准入、drain 并完成旧任务与未决证据对账，然后把新 `cube-service-harness-skill-3.0.jar` 安装到宿主 libs，合并 Provider 配置，再重启。data 输出 schema 新增 pageRef，须配套发布新 data ZIP；不能在替换 Provider 后继续执行固定旧 data schema 的任务。保留原 JAR、配置、release/policy。

```properties
# Append processing to the existing broker.providers list; keep all existing entries.
broker.provider.processing.class=cube.service.harness.skill.DataProcessProvider
broker.provider.processing.config=C:/private/harness/processing.properties
# Append data.process to execution.permissions and grant it to the trusted identity.
```

broker.providers 原列表追加 processing。复制 `service-harness-skill/config/processing.properties.template` 到上述绝对私有路径；它不需要上游地址或密钥。部署权限上限、可信身份和租户 policy 均授予 data.process。tools、普通 Runner、files、grant 和 executable 包沿用 [TOOLS.md](TOOLS.md)。

4. BZ 发布与新 JAR 匹配的 data-v1.zip 和新增 processing-v1.zip，确认 capability、time 也是获准 ready release。工具 ZIP 按现有管理员流程发布，见 [RUNTIME.md](RUNTIME.md)；F 远程资源发布权限不允许安装 executable 工具。只替换 JAR 或继续使用旧 data 摘要不能完成本次升级。
5. 将四个获准 release digest 提供给 F。在 forest 目录构包：

```text
python scripts/build_package.py --dependency common/data=<digest> --dependency common/capability=<digest> --dependency common/time=<digest> --dependency common/processing=<digest> --version 2 --output build/fhe-patrol-v2.zip
```

F 示例的 patrol-summary 用于 HTTP，uploaded-summary 用于快照。首次仅声明准备好的 connector 和分析 profiles；只主动上传时移除 HTTP connector，并只保留 uploaded-summary。将 SKILL、rules、connectors、analysis-profiles、data-processing 一并构入包。沿原管理 API validate、签名发布，再发布新 policy 并 CAS 切换；policy.skillReleases 包含业务包及四个依赖，权限增加 data.process。同名技能只固定一个 release。F 接口文档第 6 节列出签名与发布路径。

## 首次人工跑通

从 dispatcher 查询 `GET /harness/v1/task-profiles`，确认真实主模型、trusted-cpu 执行器、普通 Runner、data/processing/capability Provider 及声明的视觉能力可用，再开启接单。用自己的 Cube token 和唯一 Idempotency-Key 向 dispatcher 的 `POST /harness/v1/runs` 提交：

```json
{
  "input": {"instruction": "查询指定林区今天的巡检照片，先按区域统计并去除精确重复记录，再概述实际分析的照片，说明未覆盖范围并引用原图。", "attachmentIds": []},
  "runtime": "trusted-cpu",
  "skills": ["fhe/patrol", "common/data", "common/processing", "common/capability", "common/time"]
}
```

仅主动上传时，先按原 Input API 上传图片和 JSON 快照，真实图片 inputId 写入快照 media.inputId；任务 attachmentIds 包含两种 Input，instruction 指明快照 inputId。快照只证明上传范围，时间仍为 provider-declared。

以下是任务内工具参数，由模型调用工具，不是新增 HTTP 接口：

```json
{"action":"process","skill":"fhe/patrol","profileId":"patrol-summary","pageRefs":["<第一页pageRef>","<第二页pageRef>"]}
```

```json
{"action":"read","skill":"fhe/patrol","profileId":"patrol-summary","datasetRef":"<已返回datasetRef>","view":"groups","offset":0,"limit":8}
```

人工查看 runs/events 到终态，核对回答中的范围与记录统计，按原有可信 media-source.json 产物流程展示原图。取消/失败/unknown 任务继续不作为成功答案。模型漏步骤时保留实际 runId、事件与回答，之后再讨论验证和 M3 门禁，不把人工演示记作正式验收。源码回归入口为 service-harness-skill 的 ant test，视觉推理仍为明确标记的夹具。
